# Docs 중심 워크스페이스

[문서 목록](README.md)

## 기본 화면

- 루트는 프로젝트 목록이며 프로젝트를 열면 Docs를 기본 화면으로 표시한다.
- 기존 policies 경로도 같은 Docs 화면을 표시한다.
- 상단에는 프로젝트 목록 링크, 문서 검색, 현재 프로젝트 이름을 둔다.
- 왼쪽은 주제별 문서 목록, 가운데는 선택한 문서의 설명·규칙·근거다.
- 데스크톱 오른쪽은 콘텐츠를 배치하지 않은 여백으로 유지한다.
- 검색은 현재 프로젝트의 승인·폐기 정책 제목·카테고리·요약·규칙을 대상으로 한다.
- 폐기 정책도 사이드바와 본문에 남기고 폐기 상태와 일자를 표시한다.
- 공백으로 나눈 모든 검색어가 포함된 문서를 표시한다. 검색은 브라우저에서 수행한다.
- 검색 결과에 기존 선택이 없으면 첫 번째 결과를 표시한다.

## 우하단 플로팅 메뉴

| 메뉴 | 동작 |
| --- | --- |
| 소스 추가 | 새 업로드·기존 소스 업데이트, 등록 소스 확인, 역할 수정·삭제 패널 |
| 정책 관리 | 새 후보 및 소스 업데이트의 변경 전후 검토·승인·반려 패널 |
| 채팅 | 승인된 정책 질의와 관련 소스 추가·업데이트 안내 패널 |

메뉴는 오른쪽 여백의 우하단에 소스 추가 → 정책 관리 → 채팅 순서로 세로 배치한다.
스크롤 중에도 화면 우하단에 고정된다.
메뉴 컨테이너는 배경·외곽선·그림자 없이 버튼만 배치한다. 각 버튼은 흰색 배경과 기존 테두리를 사용한다.
현재 선택한 메뉴는 인디고 배경·글자·테두리로 구분한다.
각 메뉴는 URL에 연결되어 직접 진입할 수 있다.
패널을 닫거나 Escape를 누르면 프로젝트 기본 Docs 경로로 이동한다.
기존 dashboard 경로는 프로젝트 현황 패널로 유지한다.
정책 검토 성공 시 문서 목록 쿼리를 무효화하여 새 승인 결과를 반영한다.
소스 카드는 분석 중 1초마다 진행 API를 조회한다. 파일 기준 진행률, 현재 확인 중인 파일,
방금 찾은 정책과 누적 정책 후보 목록을 표시하며 완료 후에도 후보 목록을 유지한다.
분석이 끝나기 전 후보는 정책 관리에서 검토할 수 없다.

## 반응형과 접근성

- 폭이 좁아지면 오른쪽 여백을 숨기고 문서 영역에 공간을 할당한다.
- 데스크톱 주제 사이드바는 화면 높이에서 실제 메인 헤더 높이를 뺀 높이를 채운다.
- 주제가 적어도 사이드바는 남은 화면 높이를 채우며, 주제가 많으면 내부 스크롤한다.
- 사이드바와 문서 사이 경계선은 문서 영역에 두어 긴 문서의 맨 아래까지 이어진다.
- 문서 스크롤 중 주제 목록은 화면 상단에 고정된다.
- 모바일에서는 주제 목록을 문서 위에 배치하고 높이를 240px와 헤더를 제외한 화면 높이 중 작은 값으로 제한해 스크롤한다.
- 헤더 높이는 ResizeObserver로 측정해 화면 폭과 글꼴에 따른 높이 변경을 반영한다.
- 모바일에서도 우하단 세로 배치를 유지한다.
- 패널은 native dialog를 사용하며 제목, 닫기 버튼, Escape 동작을 제공한다.
- 검색 입력에는 접근 가능한 이름을 제공하고 선택 문서는 aria-current로 표시한다.

## 구현 위치와 확인

- 화면 조립: `apps/web/app/projects/[projectId]/[[...section]]/workspace.tsx`
- 검색·문서 선택: `apps/web/features/workspace/Docs.tsx`
- 주제 목록: `apps/web/features/workspace/DocsSidebar.tsx`
- 설명과 근거: `apps/web/features/workspace/PolicyArticle.tsx`
- 공통 패널: `apps/web/features/workspace/WorkspacePanel.tsx`
- 스타일: `apps/web/app/workspace.css`

타입 검사와 production build를 실행한다.
브라우저에서는 빈 프로젝트, 검색 결과 없음, 긴 제목, 업로드, 승인 후 문서 반영,
채팅, Escape로 닫기, 모바일 스크롤을 확인한다.
이 문서를 작성한 시점에는 브라우저 자동 UI 테스트가 구성되어 있지 않다.

대화 컨텍스트와 소스 안내는 [정책 채팅](policy-chat.md)을 참고한다.

Docs에는 소스 업데이트로 승인된 수정 이력과 이전 버전 근거를 표시한다.

## 테마와 채팅 화면

- 공통 강조색은 인디고 `#4f46e5`이며 `globals.css`의 `--primary`로 관리한다.
- shadcn/ui의 Button, Input, Textarea, Badge는 `apps/web/components/ui/`에서 관리한다.
- Tailwind CSS v4를 PostCSS로 처리하고 기존 화면 CSS는 legacy 레이어에 둔다.
- `apps/web/components.json`은 추가 컴포넌트의 위치와 별칭을 정의한다.
- 채팅은 우측 질문 말풍선과 좌측 AI 답변, 추천 질문, 하단 입력창으로 구성한다.
- 답변 근거를 누르면 다음 질문의 대상 정책을 선택한다. 소스 업데이트 링크도 유지한다.
- Enter는 전송하고 Shift+Enter는 줄바꿈한다. 한글 조합 중 Enter는 전송하지 않는다.
- 전송 중 질문과 진행 상태를 표시하며 실패하면 입력한 질문을 보존한다.
- 새 대화는 대화 내용과 선택한 정책을 초기화한다. 패널을 닫으면 대화는 보존되지 않는다.
- 채팅 스크롤과 입력창을 분리하여 긴 대화에서도 입력창을 표시한다.

확인할 상태: 추천 질문, 정책 목록 로딩·오류, 전송 중, 답변·근거·소스 링크,
전송 실패와 재시도, 새 대화, 한글 Enter, 모바일 입력창과 스크롤.

## 프로젝트 선택과 생성

- 메인은 문서와 체크 표시를 결합한 SVG 로고, 프로젝트 목록, 생성 버튼 순서로 구성한다.
- 로고는 Docs 상단에서도 같은 컴포넌트를 사용한다.
- 워크스페이스의 따뜻한 배경, 얇은 테두리, 인디고 강조색을 메인과 생성 모달에 적용한다.
- 생성 버튼을 누르면 이름과 선택 설명을 입력하는 native dialog를 연다.
- 생성 성공 시 목록을 갱신하고 모달을 닫는다. 실패 시 입력값과 오류를 유지한다.
- 닫기·취소·Escape·배경 클릭으로 닫고 생성 버튼으로 포커스를 돌린다. 생성 중에는 닫기를 막는다.
- 프로젝트 목록의 로딩·오류·빈 상태를 표시하며 오류 시 다시 시도할 수 있다.

## 공통 텍스트 크기

Tailwind의 `typography.css`에 크기·자간·행간만 정의한 6개 utility를 둔다.
색상과 굵기는 각 요소에서 지정한다.

| 클래스 | 용도 | 크기 | 자간 | 행간 |
| --- | --- | --- | --- | --- |
| `type-title` | 문서 제목 | 30px | -0.025em | 1.375 |
| `type-heading` | 섹션·모달 제목 | 20px | -0.025em | 1.5 |
| `type-subheading` | 프로젝트 이름·소제목 | 16px | 0 | 1.5 |
| `type-body` | 규칙·답변·본문 | 14px | 0 | 28px |
| `type-caption` | 안내·근거·보조 정보 | 12px | 0 | 20px |
| `type-label` | 영문 섹션 표기·메타 라벨 | 10px | 0.1em | 16px |

규칙 번호는 축소와 줄바꿈을 막고 본문만 줄바꿈한다.
근거 안내와 빈 수정 이력은 같은 `evidence-description type-caption`을 사용한다.
로고 글자는 브랜드 표현으로 별도 유지한다.
아티클 하단 패딩은 32px로 두며 중간 화면 폭에서 콘텐츠에 추가 하단 패딩을 붙이지 않는다.
화면에 들어가는 짧은 문서는 페이지 스크롤을 만들지 않고, 긴 내용은 자연스럽게 스크롤한다.

전체 화면은 body의 Tailwind `break-keep`으로 한글 어절을 유지한다.
긴 단일 문자열은 필요할 때만 줄바꿈하고, 근거 파일 경로는 `break-all`, 코드 원문은 가로 스크롤을 유지한다.
