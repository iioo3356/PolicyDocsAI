# 개발 문서 안내

처음 작업할 때는 개발 규칙을 읽고, 변경하는 영역의 문서를 확인한다.
문서의 **현재 동작**, **작성 기준**, **미구현 개선 항목**을 구분한다.
작성 기준은 신규·변경 코드에 적용하며 기존 코드 전체가 이미 준수한다는 뜻은 아니다.

| 문서 | 확인할 때 |
| --- | --- |
| [개발 규칙](development-rules.md) | 파일 크기, 클래스 분리, 계층과 의존성 방향 |
| [Python 작성 기준](python-guide.md) | 타입, 데이터 모델, 오류, 동기·비동기, 시간, 로깅 |
| [데이터와 작업 처리](data-lifecycle.md) | DB 트랜잭션, 업로드·삭제, 승인·병합, 분석 작업 변경 |
| [테스트 가이드](testing.md) | 실행 명령, 격리된 테스트 작성, 변경별 검증 범위 |
| [문서 자동 검증](documentation-checks.md) | 문서를 다시 읽기 전 정적 근거·링크·명령 검사 |
| [정책 채팅](policy-chat.md) | 승인 정책 질의, 소스 업데이트 안내와 실패 처리 |
| [소스 업데이트](source-updates.md) | 관련 소스 재업로드, 변경 전후 승인, 영속 수정 이력 |
| [워크스페이스 UI](workspace-ui.md) | Docs 레이아웃, 검색, 플로팅 메뉴와 반응형 동작 |
| [개선 과제](engineering-backlog.md) | 현재 제약과 후속 구현의 완료 기준 |

설치·환경변수·사용법은 [프로젝트 README](../README.md)를 참고한다.
구현을 바꾸면 해당 문서와 회귀 테스트도 함께 갱신한다.
문서와 코드가 다르면 현재 코드의 동작부터 확인하고, 의도한 변경인지 결정한다.

문서를 검토하기 전 `make check-docs`를 실행하고, 오류가 지목한 부분부터 확인한다.
기계 처리에는 `python3 scripts/check_docs.py --json`을 사용한다.
